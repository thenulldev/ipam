# ipam-v0.2.0 (pending — not yet cut)

This release will be the first tagged build on top of the NUL-19 green
quality baseline.

## Will include

- CI gating on a fresh checkout: `npm ci`, `npm run lint`, `npm run
  typecheck`, `npm test`, `npm run build`, `npm run build:server`,
  `npm run clean-db-smoke`, `npm run backup:restore:test`.
- Multi-stage `Dockerfile` with `HEALTHCHECK` against `/healthz`.
- `scripts/backup.ts`, `scripts/restore.ts`, and
  `scripts/ops/backup-restore-test.ts` (round-trip verified in CI).
- `scripts/ops/clean-db-smoke.ts` proving a fresh-empty-data-dir boot
  serves `/healthz` 200 with seeded tenants.

## Will NOT include

- Structured request logging or `/metrics` endpoint. Deferred until
  NUL-15 (install & deploy hardening) is stable; bad infra + new logs
  makes flakes worse.
- First-class QA tooling. Flaky tests, when they appear, will be
  quarantined in CI pending a QA hire.

## Upgrade notes

- No DB migrations are bundled with this release. Schema is created on
  first boot via Drizzle. Existing operators can `git pull` and restart;
  the server will run any pending migrations on start.
- `IPAM_DATA_DIR` defaults to `./data`. Override per environment.

## Known watch-fors

- The first boot against an empty `IPAM_DATA_DIR` runs the seed
  synchronously — expect a one-time ~2s pause before `/healthz` returns
  200. Subsequent boots are fast.
